## Known issues

- **Rules-only scores are modest.** With no model and no lookalike detection yet, several clear scams land in `suspicious` (e.g. C's `sample-fake-kyc` scores 47, `sample-electricity-hi` 52). Golden tests use "flagged" (scam or suspicious) for those and will tighten in P2/P3.
- **Fusion tweak:** the links layer joins the weighted average only when its score is > 0 (SPEC_A §8.2 says "when links/UPI IDs exist"). An unflagged link is absence of evidence; counting it as 0 pulled every message with a link down by ~30%. C's calibration may revisit.
- **Floor added:** `ASKS_OTP` has a floor of 45 (not in §5.2) so a message whose only sign is an OTP request never reads "No warning signs found" while showing an "Asks for your OTP" signal. Other credential asks already reach ≥ 45 by weight.
- **Category choice** votes by summed weight of category hints (SPEC_A §8.4 step 3 says "highest-weighted rule signal"); `categoryConfidence` is the winning share. Votes fix cases like an OTP ask inside a KYC message (`fake_kyc`, not `otp_theft`).
- `emergency` is added only when the user's own words say money left (collect-request note, or "me" chat turns) — a scammer's "I sent you money by mistake" must not trigger it.
- `claimedAs` is keyword-based: "electricity officer" reads as `police`.
- Telugu negation uses the negative-imperative endings (`వద్దు`, `-కండి`); a positive imperative that happens to end in "కండి" would be misread as negated.
- The Write/Edit tools on this laptop turn typed `\uXXXX` escapes into literal characters, and the Bash tool collapses `\\`; Unicode ranges are written as code-point checks or `\p{Script=…}` to stay safe.
- Carried from Phase 0: root `build`/`dev`/`eval` use `--workspaces --if-present`; TypeScript pinned to `~6.0.3` for typescript-eslint; Vercel compiling `api/*.ts` that import `.ts` workspace sources is unverified (check at the first preview deploy in P3); `normalizeText` collapses newlines (chat/email text is one line, turns carry offsets); `OcrResult.confidence` is 0–100; `UpiIdFinding.handle` is the part after `@`; `eval-report.json` numbers are placeholders.
