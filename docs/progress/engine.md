## Known issues

- Root `build`, `dev` and `eval` scripts use `--workspaces --if-present` instead of `-w @akshi/web --if-present` / `-w @akshi/eval --if-present` (SPEC_A §2.1): npm errors on `-w <name>` when that workspace does not exist yet, which would break CI until B and C push. Behaviour is the same once the workspaces exist. `vercel.json` keeps `npm run build -w @akshi/web` as specified (Vercel builds fail until `apps/web` exists — expected per SPEC_A §2.5).
- TypeScript pinned to `~6.0.3`: TS 7.0 is the npm `latest`, but typescript-eslint 8.72 supports `<6.1`.
- Root `tsconfig.json` references do not include `apps/web` or `eval` yet; `tsc -b` would fail on a missing reference. A adds them when B/C push (see Requests).
- Vercel compiles `api/*.ts` itself; whether it follows imports into workspace packages whose `exports` point at `.ts` source (`@akshi/contracts`, `@akshi/engine`, `@akshi/content`) is unverified. Check on the first preview deploy in P3; fallback is bundling `api/` with esbuild or emitting JS for the packages.
- `normalizeText` collapses newlines, so chat and email `text` is a single line; `ChatTurnRisk` offsets mark turn boundaries.
- QR fixture `text` is the percent-decoded payload (`pn=SBI Refund`), so highlights read naturally; `qr.raw` keeps the encoded string.
- `OcrResult.confidence` is 0–100 (tesseract scale, matching SPEC_A §10 "< 55"); `AnalysisResult.confidence` is 0–1.
- `UpiIdFinding.handle` is the PSP handle after `@` (e.g. `ybl`); `psp` is the app name (e.g. `PhonePe`).
- `eval-report.json` numbers are invented placeholders and say so in `notes`; B must not present them as measured.
